# 확장 계획과 설계 판단 메모

이 문서는 "왜 이렇게 만들었나"와 "다음에 무엇을 할 수 있나"를 정리한다. 발표 질의응답과 결과 보고서의 한계·향후 계획 절에 그대로 쓸 수 있다.

## 1. 대상 확장: WISH는 첫 번째 적용 대상일 뿐이다

- 이 프로젝트의 핵심은 "자막이 있는 영상 모음에서, 어렴풋한 기억 설명으로 장면의 시점을 찾는다"이다. NCT WISH는 팬인 사용자가 정한 **첫 적용 대상**이고 범위를 줄이기 위해 먼저 택했다. 제품 정의가 WISH에 묶여 있지 않다.
- **코드에서 대상에 묶인 곳은 이번에 모두 정리했다.**
  - 공통 프롬프트의 대상 이름 → 일반 문구
  - 자막 속 이름 감지 정규식 → 대상 프로필의 이름 사전
  - 화면 문구 → 대상 비종속 문구
- **대상 프로필**(`data/profile.local.json`, 예시는 `data/profile.example.json`, 코드는 [profile.py](../backend/app/profile.py))이 대상별 지식을 담는다.
  - 자료 이름, 자막 언어, 번역 자막 여부와 원래 말의 언어, 자주 나오는 이름(표기와 별칭), 짧은 메모
  - 프로필이 없으면 기본값(일반 모음)으로 동작한다. 형식이 틀린 파일은 시작 때 오류로 알려 준다.
- **새 대상을 붙이는 방법**: 영상 목록(manifest)에 자막 파일을 등록하고, 프로필에 이름 사전과 언어를 적는다. 코드는 그대로다.

## 2. 자막 형식과 언어

- **형식은 SRT로 고정**한다. 다른 형식(VTT 등)은 SRT로 변환하는 어댑터를 앞에 붙이는 방식으로 풀 수 있다(검색·검증 코드는 SRT cue 구조에만 의존한다).
- **언어는 프로필의 `subtitle_language`를 따른다.** Router가 이 언어로 검색어를 만들고 번역 여부는 프롬프트에 반영된다. 영상 정보(`Video`)에 `language` 필드가 이미 있으나 아직 어디에서도 쓰이지 않는다.
- **언어가 바뀔 때 깨질 수 있는 곳**(알려진 한계, 이번 범위 밖)
  1. **BM25 단어 검색**: 공백으로 단어를 자른다([hybrid.py](../backend/app/retrieval/hybrid.py)). 일본어·중국어·태국어처럼 띄어쓰기가 없는 언어는 한 문장이 단어 하나가 되어 단어 검색이 사실상 동작하지 않는다. 글자 n-gram 같은 언어별 분절이 필요하다.
  2. **뜻 검색(bge-m3)** 은 다국어를 이해하므로 부분적으로 보완하지만, 영어 외 언어에서의 정확도는 측정하지 않았다.
  3. **한 영상에 여러 언어 자막 트랙**이 있으면 트랙을 별도 영상으로 등록하는 규칙이 필요하다.
  4. **인코딩**: UTF-8(BOM 포함)만 읽는다. 다른 인코딩은 거부한다.
- 단계: (1) 프로필 언어 사용(완료) → (2) 영상별 `language`로 검색어 언어 선택 → (3) 언어별 단어 분절 → (4) 언어별 소규모 평가셋.

## 3. 번역 자막(한국어·일본어 대화, 영어 자막)을 프롬프트에 반영한 이유

못 찾은 질문을 trace로 열어 보니 원인 중 하나가 **번역된 자막의 단어와 질문의 단어가 다른 것**이었다. 그래서 프롬프트에 다음을 넣었다(대상 비종속 일반 원칙 + 프로필 정보).
- 자막은 번역이라 단어가 달라도 뜻이 같으면 인정한다(판정).
- 검색어에 핵심 명사의 동의어·다른 표기를 함께 넣는다(Router), 재검색에서는 **동사만이 아니라 핵심 명사를 바꾼다**(Rewrite).
- 자주 나오는 이름의 표기를 프로필의 이름 사전으로 알려 준다.
- 화자 질문에서 "누가 말했는지 알 수 없다"는 판정을 낮추는 이유가 아니다. 자막에는 화자가 없고 결과에도 "화자 확인 불가"가 항상 표시되기 때문이다.
- 효과의 크기는 가정하지 않고 같은 gold로 전/후를 측정했다([day2-eval-openai.md](reports/day2-eval-openai.md)).

## 4. 왜 단일 Agent이고, Multi-Agent는 향후 과제인가

**현재 구조**: 하나의 LangGraph와 State를 공유하는 **역할 분리된 단일 Agent**다(Router / Searcher / Verifier / Replanner / Finalizer 노드). 서로 협상하는 독립 Agent가 아니므로 "Multi-Agent"라고 부르지 않는다.

**지금 Supervisor + 전문 Agent로 나누지 않는 이유**
- 일이 순서대로 짧다(LLM 호출 2~6회). 서로 독립적이라 병렬로 할 일이 없다.
- 도구가 3개이고 호출 순서가 정해져 있다. 어떤 도구를 쓸지 LLM이 고를 필요가 없다.
- Supervisor는 "누구에게 맡길지"를 정하는 **LLM 호출을 추가**한다. 지연, 토큰, 비용, 실패 지점이 늘어난다. 마감과 응답 시간 목표(약 12초 이내) 안에서 이득이 불분명하다.
- 문제의 원인은 구조가 아니라 검색 어휘와 판정 기준이었다(진단 결과).

**나누는 편이 나아지는 경우**: 자료 종류가 늘어날 때(영상, 이미지, 문서), 도구가 많아져 LLM이 골라 써야 할 때, 서로 독립적인 조사를 병렬로 해야 할 때.

**향후 실험 설계** (기본 동작은 바꾸지 않고 플래그로 켜는 실험용 구조)
| 구성 | 역할 |
|---|---|
| Supervisor | 질문을 보고 전문 Agent에게 일을 맡기고 결과를 모아 종료 판단 |
| Search Agent | MCP 도구를 **스스로** 여러 번 호출(다른 검색어, 인접 구간 확인) |
| Verifier Agent | 후보 판정 |

- 비교 조건: 같은 gold, 같은 LLM·프롬프트 기반, 질문당 1회 이상.
- 비교 지표: 장면 Success@1·Hit@3, 화자 질문 정확도, 확신 오답, 지연, LLM 호출 수, 토큰(비용), 재시도 횟수.
- 가설: 자율 검색은 재현율을 올릴 수 있지만 호출 수와 지연이 늘어난다. **결과가 어느 쪽이든 측정해서 보고한다.**

## 5. MCP 도구를 3개로 나눈 이유

| 도구 | 하는 일 | 특징 |
|---|---|---|
| `search_transcripts` | 질문으로 후보 청크 검색 | 무겁다(임베딩 계산). 동시에 하나만 실행(잠금) |
| `get_scene_context` | 특정 영상·시간 주변의 **원본 자막** 조회 | 가볍다. 검증의 근거 |
| `get_video_metadata` | 영상 제목·주소·검증 상태 | 서버 시작 때 한 번만 읽어 캐시 |

1. **하는 일과 무게가 다르다.** 한 도구에 합치면 가벼운 조회까지 무거운 검색의 잠금에 막힌다. 지금은 검색에만 잠금이 걸린다.
2. **원문 조회는 검증용 "진실의 창구"다.** 검색이 돌려준 청크를 믿지 않고, 다른 경로로 원본 자막을 다시 읽어 시각·영상·cue를 대조한다. 검색 도구가 원문까지 같이 주면 청킹 오류가 검증에도 그대로 전파된다.
3. **LLM과 코드가 파일 경로를 다루지 못한다.** 도구 인자에 경로가 없고 등록된 영상 ID만 받는다.
4. **교체·테스트가 쉽다.** 검색 방식이나 자료를 바꿔도 원문 조회는 그대로이고, 도구별로 가짜(mock)를 만들 수 있다.
5. **MCP 도구 설계 원칙**: 작고 조합 가능한 도구, 타입이 있는 입출력, 사람과 LLM 모두 읽을 수 있는 설명.

**대가**: 도구 호출이 늘어난다(질문당 4~5회, 한 라운드에 후보마다 문맥 조회). 각각 수 ms 수준이라 전체 지연에 영향이 작다.

**솔직한 한계**: 현재는 **그래프 코드가 도구를 정해진 순서로 호출**하고, LLM이 도구를 고르지 않는다(function calling 아님). MCP를 "LLM이 자율적으로 도구를 쓰는 구조"가 아니라 "자료 접근의 안전한 경계와 표준 인터페이스"로 쓰고 있다. 4장의 Search Agent 실험이 이 부분을 바꾸는 시도다.

## 6. 알려진 한계 (요약)
- 영상·음성을 분석하지 않는다. 자막(번역본)만 사용한다. 화자는 알 수 없다.
- gold는 장면당 정답 하나만 잡아서, 같은 말을 하는 장면이 여럿이면 다른 장면을 `found`로 반환해도 오답으로 집계된다.
- 평가는 질문당 1회, 18문항이라 1~2문항 차이는 노이즈다. 모델이 달라지면 점수가 달라진다.
- 영어 외 자막과 띄어쓰기 없는 언어는 검증되지 않았다.
