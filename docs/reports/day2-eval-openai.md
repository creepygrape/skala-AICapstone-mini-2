# Day 2 평가 (OpenAI 백엔드) — A=BM25 / B=Hybrid / C=Hybrid+Agent

- 날짜: 2026-10-21
- 상태: **실측 완료(질문당 1회).** 반복·분산은 측정하지 않았다.
- 공개 범위: 집계 수치만 기록한다. 질문 원문·정답 구간·자막 인용·개별 결과는 `eval/private/`(Git 제외)에만 있다.
- 관련: [ADR-0008](../adr/0008-llm-backend-switch.md), Ollama 기준 측정 [day2-eval.md](day2-eval.md)

## 설정

- **LLM**: `WISH_LLM_BACKEND=openai`, route·rewrite는 `gpt-4o-mini`, verify는 `gpt-4o`(`temperature=0`, `seed=42`, strict Structured Outputs). 프롬프트·스키마·그래프·검색·gold·질문은 Ollama 측정과 같다(`JsonLLM` 공통 계약).
- gold: 사람이 승인한 20문항(승인 해시 검증). 장면 정답이 있는 질문 18개, 시각·청각 전용 요청 2개.
- 실행: `eval.run_eval --systems A,B,C --control --langsmith --max-llm-calls 150`. A/B는 LLM을 쓰지 않는다.
- 외부 전송: gold 질문과 후보 자막(요청당 최대 3구간, 20초 문맥)이 OpenAI와 LangSmith(`wish-finder-eval` 프로젝트)로 전송됐다(ADR-0008 승인 범위).

## 실행 이력 (둘 다 1회, 같은 gold)

| 실행 | 결과 | 비고 |
|---|---|---|
| v1 | 불완전(`complete=false`), C·C-ko 각 2건 오류 | 시각·청각 전용 질문 2개에서 Router가 빈 `search_query`를 돌려줘 `model_invalid_response`. 검색하지 않는 의도에서 빈 검색어를 거부한 **계약 결함**(ADR-0008 "발견된 결함과 수정") |
| **v2 (최종)** | **완료, 120건, 오류 0건** | 결함 수정(A안) 후 같은 gold로 다시 측정. 아래 표는 v2 기준 |

- 결함은 평가 결과를 보고 발견했지만 **프롬프트·검색·판정 로직은 바꾸지 않았다.** 수정은 "검색하지 않는 의도의 빈 검색어 허용"이라는 검증 규칙 하나이며 장면 질문의 동작과 무관하다.
- v1 수치는 제출 수치로 쓰지 않는다. 다만 v1과 v2에서 장면 질문 결과가 1문항 달랐다(아래 "비결정성").

- **LangSmith 화면 확인(사용자 캡처)**: 프로젝트 `wish-finder-eval`에 트레이스 80개, 총 토큰 61.1K, 비용 $0.1466, 오류율 0%가 표시됐다. 토큰은 위 로컬 합계(56,941 + 4,125 = 61,066)와 일치한다. 트레이스 80개는 C·C-ko 40회 × (그래프 트레이스 1 + 요약 기록 1)로 보는 것이 맞아 보이나, 개수의 내역은 화면에서 직접 구분하지 않았다.
- **비용**: 위 $0.1466은 **LangSmith가 모델명과 토큰으로 계산한 값**이며 실제 청구액과 다를 수 있다. 실제 청구액은 OpenAI 대시보드가 기준이다. 사전 추정(전부 gpt-4o 단가로 약 0.18달러 상한)과 같은 범위에 있다.
- 지연은 OpenAI 네트워크 호출 기준이며 Ollama(로컬 CPU 추론, 약 12초)와는 실행 환경이 다르다. 직접 비교하지 않는다.

## 비결정성 (v1 대 v2)

같은 설정(`temperature=0`, `seed=42`)과 같은 gold로 두 번 실행했을 때 C의 장면 질문 결과가 1문항 달랐다.
- v1: 17/18 (한 질문이 `found`)
- v2: 16/18 (같은 질문이 `ambiguous`로 끝나 성공에서 제외, 원시 후보 적중은 17/18)
- 화자 미확인도 이에 따라 3/4 → 2/4로 바뀌었다(같은 질문).

따라서 **1문항 차이는 노이즈 범위**이며, 이 표본으로 C와 B의 순위나 Ollama와의 우열을 단정할 수 없다. OpenAI는 같은 시드에서도 완전한 재현을 보장하지 않는다.

## 개선 전/후 (v2 → v3, 같은 gold·같은 모델·같은 첫 질문)

v3는 [ADR-0009](../adr/0009-collection-profile-and-retrieval-judging-fixes.md)의 변경(화자 질문 판정 기준, 번역 자막·이름 사전 프롬프트, 중복 재검색 제거, 거절 후보 인용문을 보여 주는 재작성)을 적용하고 **같은 명령으로 다시 측정**한 결과다. 완료, 120건, 오류 0건.

| 지표 | v2 (전) | v3 (후) |
|---|---|---|
| C Scene Success@1 / Hit@3 (장면 18문항) | 16/18, 16/18 | 16/18, 16/18 |
| C 상태 분포 | found 16, ambiguous 1, not_found 1, unsupported 2 | found 17, not_found 1, unsupported 2 |
| C 화자 미확인 정확도 | 2/4 | **3/4** |
| C unsupported 정확도 | 2/2 | 2/2 |
| C 확신 오답 | 0 | 1 |
| C-ko Success@1 / 화자 / 확신 오답 | 16/18, 3/4, 1 | 16/18, 3/4, 1 |
| B router_en Success@1 / Hit@3 | 13/18, 16/18 | **15/18**, 16/18 |
| A router_en Success@1 / Hit@3 | 5/18, 5/18 | **13/18**, 15/18 |
| C 전체 LLM 호출 | 50 | **42** |
| C 평균 / 최대 지연 (초) | 2.88 / 6.26 | **2.57** / 6.74 |
| C 입력 / 출력 토큰 | 29,351 / 2,090 | 33,753 / 1,717 |
| C-ko LLM 호출 / 입력·출력 토큰 | 48 / 27,590·2,035 | 48 / 37,017·1,951 |
| 전체 LLM 호출 / 입력·출력 토큰 (C+C-ko) | 98 / 56,941·4,125 | **90** / 70,770·3,668 |

**무엇이 달라졌나 (문항 유형으로 기술)**
- **화자 질문 1건**: `ambiguous`(3라운드, LLM 6회) → `found`(1라운드, LLM 2회). 판정 기준 변경(화자를 알 수 없다는 것은 판정을 낮추지 않음)과 중복 재검색 제거가 의도한 대로 작동했다.
- **재검색으로 찾던 질문 2건**: 2라운드 → 1라운드로 단축(Router의 동의어 포함 검색어가 첫 라운드에서 적중).
- **같은 말을 하는 장면이 여럿인 질문 1건**: v2에서는 gold 장면(영상 후반)이 반환됐으나 v3에서는 영상 초반의 **다른 비슷한 장면**(약 3분 40초 부근)이 `found`로 반환되어 오답 집계(확신 오답 +1). 같은 질문이 C-ko에서는 v2·v3 모두 그 초반 장면(약 3분 30초)을 반환했다. Router의 첫 검색어가 바뀐 것(`camping suddenly heavy rain` → `camping rain heavy`)이 검색 결과를 바꿨으므로, 라벨 한계(유사 장면 다수)와 함께 **이번 프롬프트 변경이 이 질문에서는 불리하게 작용했을 가능성**도 있다. 1회 측정이라 원인을 분리하지는 못했다.
- **여전히 못 찾는 질문 1건(`not_found`)**: 정답이 후보에 오르지 않는 검색 어휘 문제로, 이번 변경으로 해결되지 않았다.
- **A/B router_en 상승**: A/B는 C의 Router 첫 검색어를 재사용한다. 검색어에 핵심 명사의 동의어를 함께 넣게 하자 단어 검색(A)이 5→13으로 크게 올랐고 Hybrid(B)도 13→15가 됐다. 이 상승은 Router 프롬프트 변경의 효과다(Agent의 재검색·판정과 무관).
- **비용 구조**: 호출은 줄었지만(98→90) 시스템 메시지에 프로필·규칙이 추가되어 **입력 토큰은 늘었다**(C+C-ko 56,941 → 70,770, 약 +24%). 호출 수와 토큰은 서로 다른 방향으로 움직인다.

**해석과 한계 (과장하지 않기 위해)**
- C의 장면 정확도 헤드라인(16/18)은 **변하지 않았다.** 한 문항을 얻고(화자 질문) 한 문항을 잃었다(유사 장면이 여럿인 질문). 개선의 확인된 이득은 **화자 질문 판정, 재검색 효율(호출·지연), A/B의 검색어 품질**이다.
- v1 → v2에서도 같은 설정으로 1문항이 달라졌으므로(비결정성) **1문항 단위 변화는 노이즈일 수 있다.**
- 이 개선은 **gold의 실패 사례를 본 뒤** 한 것이라 낙관 편향이 있다. 변경 자체는 문항 문구가 아닌 일반 원칙(프롬프트, 프로필, 중복 제거)이지만, 별도의 hold-out 질문으로 확인하지는 못했다.
- 이번 실행도 질문당 1회이며 반복·분산은 측정하지 않았다.

## 해석

1. **Agent 효과**: OpenAI에서 C(16/18)가 B(router_en 13/18, raw_ko 11/18)보다 3~5문항 높다. 같은 첫 검색어 기준(router_en)에서도 C가 높아 의미 검증과 재검색의 기여를 시사하지만, 1회 실행이라 유의하다고 말할 수 없다.
2. **백엔드 효과**: Ollama 대비 C가 12→16, B router_en이 10→13, A router_en이 1→5로 올랐다. Router가 만든 영어 검색어와 판정 모델의 품질 차이가 섞여 있고, 이 실험만으로는 둘을 분리하지 못한다.
3. **안전성**: 근거 없는 화자 단정 0건, 시각·청각 요청 2/2 거부는 유지된다. 확신 오답은 C 0건, C-ko 1건이다.
4. **남은 실패**: C는 화자 질문 계열 2건에서 `ambiguous`/`not_found`로 끝났다(한 질문은 v1과 달라짐).

## 한계

- 질문당 1회, 18문항 표본이라 1~2문항 차이는 노이즈다. 반복 분산, p95는 측정하지 않았다. not_found 정확도는 확정 부재 질문이 없어 측정 불가다.
- 실행 순서가 고정이라(C 전체 → A/B raw_ko → C-ko → A/B router_en) 캐시 워밍이 뒤 조건에 영향을 줄 수 있다.
- 사람이 판정한 의미 품질은 측정하지 않았다. gold 시각은 영상 표본 확인만 했다.
- LangSmith 화면은 작성자가 직접 보지 못했고 사용자가 제공한 캡처(프로젝트 목록 화면)로만 확인했다. 호출별 트레이스 상세는 캡처에 없다.
- 개발(Ollama)과 시연·제출(OpenAI)의 수치는 서로 다른 모델 조건이다. 제출 문서에는 이 보고서의 수치를 쓰고 모델명을 함께 적는다.
