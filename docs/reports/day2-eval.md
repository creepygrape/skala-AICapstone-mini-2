# Day 2 평가 — A=BM25 / B=Hybrid / C=Hybrid+Agent

- 날짜: 2026-10-21, 브랜치: main 기반 작업 트리(미커밋)
- 상태: **실측 1회 완료.** 질문당 1회 실행이며 반복·분산은 측정하지 않았다.
- LLM 백엔드: **이 문서의 C 수치는 전부 로컬 Ollama `qwen3:8b` 기준**이다. 시연·제출용 OpenAI 백엔드(ADR-0008) 수치는 미측정이며, 과금 실행이라 별도 승인 후 다시 측정한다.
- 공개 범위: 집계 수치와 일반화한 실패 유형만 기록한다. 질문 원문·정답 구간·자막 인용·개별 결과는 `eval/private/`(Git 제외)에만 있다.

## 설정

- gold: 사람이 승인한 20문항(`gold-approval.json`의 해시와 실행 시 일치 확인). 장면 정답이 있는 질문은 **18개**(일반 장면 13, 복수 장면 1, 화자 미확인 4). 시각·청각 전용 요청 2개는 unsupported 정확도에만 쓴다. 부재 후보 4개는 사람 확인 전이라 제외했으므로 **not_found 정확도는 측정 불가**다.
- 같은 corpus(영상 3편)·질문·정답. 성공 기준은 기존과 같다: 영상 일치 + 실제 링크 시각 `floor(start)`가 허용 구간 ±10초.
- C: 실제 `FinderAgent`(LangGraph, 최대 3라운드), 로컬 Ollama `qwen3:8b`(`temperature=0`, `seed=42`), 같은 MCP stdio 세션. 신규 의존성·유료 호출 없음. LangSmith는 끄고 로컬 JSON만 사용했다. **Agent 코드는 평가를 위해 수정하지 않았다.**
- 실행: `python -m eval.run_eval --dataset eval/private/gold.jsonl --systems A,B,C --control --output eval/private/day2-abc-gold.json` (120건 전부 실행, 오류 0건).

## 검색어 전처리 차이와 통제 실험

| 조건 | 첫 검색어 | 비교 의미 |
|---|---|---|
| `raw_ko` A/B | 사용자 한국어 원문(길이·공백 검사만) | 기존 Day 1 방식 |
| `router_en` C | Router(LLM)가 쓴 영어 검색어 → 이후 재작성도 LLM | 제품 실사용 경로 |
| `router_en` A/B | C의 Router 첫 검색어를 그대로 재사용 | **A/B/C 같은 첫 검색어** |
| `raw_ko` C-ko | 한국어 원문으로 첫 검색어를 대체, Router 의도 분류는 그대로 | **Agent의 Router 재구성 효과를 분리한 통제** |

A/B(`raw_ko`)와 C(`router_en`)는 전처리가 달라 직접 비교하면 Router 효과가 섞인다. 같은 첫 검색어 비교는 `router_en`의 A/B/C와 `raw_ko`의 A/B/C-ko다. 단, 재검색 검색어는 C/C-ko만 LLM이 만든다.

- 화자 단정: 사용자에게 보이는 `explanation_ko`는 코드의 고정 문구 4종뿐이며(검증 상태 + "자막만으로 화자를 확인할 수 없습니다" 유무) 발화자를 지목하는 문구가 없다. 따라서 필드·설명문 모두 0건이다. 이는 모델 자유 생성이 없는 설계의 결과이며 Router의 화자 추론 능력을 뜻하지 않는다.
- 화자 미확인 4문항 중 3개가 세 조건을 모두 통과했고, 실패 1개는 의도·안내는 맞았으나 **장면 검색에 실패**한 경우다(C, C-ko 동일 문항).

## 실패 사례와 해석

1. **장면 검색 실패(6/18, 두 C 조건에서 대부분 공통)**: 일부 질문은 B에서도 찾지 못했다. Agent 재검색(최대 2회)이 이를 구제하지 못했고 `not_found`/`ambiguous`로 끝났다.
2. **확신 오답(found인데 틀림)**: C 2건, C-ko 2건(`eval.aggregate`로 비공개 결과에서 재집계; status=found이면서 Success@1 실패). C-ko의 나머지 장면 실패는 `not_found`였다. 의미 검증 모델(qwen3:8b)이 관련 있다고 판정했으나 gold 구간과 다른 장면이었다. 검증이 근거 위조는 막지만 장면 일치까지 보장하지 못한다.
3. **Router 오분류**: 자막으로 찾을 수 있는 장면 질문 1건을 `unsupported`로 분류해 검색하지 않았다. B는 같은 질문을 찾았으므로 Agent가 오히려 성공을 막은 사례다.
4. **화자 의도 과분류**: 화자 질문이 아닌 장면 질문 2개도 `speaker_query`로 분류됐다. 안내 문구가 추가될 뿐 결과는 같지만 의도 정밀도는 4/6이다.
5. **재검색 효과**: C에서 첫 라운드 실패 후 재검색으로 성공한 문항은 2건(router_en), C-ko에서는 0건이었다. 재검색은 최대 3라운드까지 쓰이고 지연을 크게 늘린다.

## 결론과 한계

- **Agent의 장면 정확도 이점은 이 표본에서 입증되지 않았다.** C(12/18)와 B(raw_ko 11/18, router_en 10/18)의 차이는 1~2문항이며 18문항 1회 실행으로는 유의하지 않다. 한 문항만 달라져도 순위가 바뀐다.
- 확인된 차이는 기능적 안전성이다: unsupported 요청 2/2 거부, 화자 미확인 안내, 의미 검증을 통과한 근거만 반환. 대가는 이 실행 조건에서 관측한 평균 지연 약 50~70배(0.17–0.25초 → 약 10–12초)와 LLM/Tool 호출 증가다.
- A(BM25)는 한국어 질의로는 사실상 동작하지 않는다(0/18). 영어 Router 질의에서도 1/18이다.
- 통제 실험상 Router의 영어 재구성이 C의 이점이라고 볼 근거는 없다. 한국어 원문 첫 검색어(C-ko)가 같은 성공 수(12/18)에 더 적은 호출을 썼다.
- **지연·호출 비교의 한계**: 실행 순서가 고정이었다(C 전체 → A/B raw_ko → C-ko → A/B router_en). 같은 MCP/Retriever를 재사용해 임베딩·cue 검증 캐시가 첫 구간(C) 이후 워밍된 상태로 뒤 조건이 실행됐고, 모델·인덱스 초기화 시간은 지연에서 제외했으며 캐시는 초기화하지 않았다. 질문당 1회 실행이다. 따라서 C와 C-ko의 지연·호출 차이에는 Router 검색어 효과 외에 재검색 예산·캐시·실행 순서가 섞여 있을 수 있다. 분리하려면 워밍 조건 통일 또는 순서 교차 반복이 필요하며 이번에는 수행하지 않았다.
- **성공 정의**: C의 Scene Success@1/Hit@3와 화자 정답은 `status=found`만 인정한다. `partial`·`ambiguous`는 원시 후보 적중을 `retrieval_metrics`로 따로 남기며 성공에 넣지 않는다. 이번 저장 결과에서는 non-found 정답 후보가 없어 12/18이 바뀌지 않았다(`python -m eval.aggregate`로 확인). 오류·fallback 시 LLM 호출 수는 모델 래퍼가 센 값을 쓰고, fallback 원인은 `telemetry_error`로 보존한다.
- 미측정: not_found 정확도, 반복 실행 분산, p95, 사람이 판정한 의미 품질, 다른 LLM, LangSmith 추적. gold 시각은 영상 표본 확인만 했고 전수 검증이 아니다. 이번 평가에서는 gold 결과를 본 뒤 Agent·프롬프트를 조정하지 않았다(1회 실행 후 그대로 보고).
- 재현: 실제 자막은 공개하지 않으므로 제3자가 같은 corpus 결과를 재현할 수 없다. 합성 fixture 기반 테스트(101개 통과)는 C 경로·지표·승인 해시 검증을 확인한다.
