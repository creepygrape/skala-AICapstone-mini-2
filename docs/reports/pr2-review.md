구현은 `backend/app/services/search.py`, `eval/run_eval.py`, `eval/metrics.py`, `eval/paths.py`, `eval/dataset.py`가 담당한다. ADR 0001·0002·0004와 평가 안내를 갱신했다. 실제 라벨의 중복 시각 필드만 제거했으며 질문·정답·초안 승인 상태는 바꾸지 않았다.

## 동일 개발셋 Before / After

같은 3편·3,750 cue·개발 질문 5개·고정 영어 검색어를 사용했다. 각 조건 문항당 1회이며 원래 결과 `eval/private/day1-baselines.json`을 보존하고 수정 후 `eval/private/day1-baselines.review2.json`에 별도 저장했다. 영어 검색어를 다시 생성하거나 오류를 교정하지 않았다.

| 조건 | 방식 | Success@1 이전 → 이후 | Hit@3 이전 → 이후 | 평균 초 이전 → 이후 |
|---|---|---|---|---|
| 한국어 원문 | A BM25Plus | 0/5 → 0/5 | 0/5 → 0/5 | 0.0017 → 0.0016 |
| 한국어 원문 | B Hybrid | 3/5 → 3/5 | 4/5 → 4/5 | 1.2508 → 0.9983 |
| 고정 영어 | A BM25Plus | 2/5 → 2/5 | 2/5 → 2/5 | 0.0051 → 0.0048 |
| 고정 영어 | B Hybrid | 2/5 → 2/5 | 3/5 → 3/5 | 0.4335 → 0.3402 |

수정 후 20회 모두 실행됐고 오류 0건, `complete=true`다. MCP 초기 연결 준비는 4.051초(이전 6.205초)이며 개별 검색 latency에서 제외한다. 메타데이터 준비도 개별 검색 측정 밖이다. 실행 순서·캐시·소표본 영향을 통제하지 않았으므로 시간 감소를 성능 개선으로 결론 내리지 않는다.

개발셋에는 부재·화자 전용 문항이 없어 해당 정확도는 분모 0, N/A다. 범위 밖 정확도는 A/B에 의도 라우터가 없어 N/A다. 근거 없는 화자 단정은 반환 결과에서 0건이지만 화자 질문 정확도를 측정한 것은 아니다. 관련 지표의 오류·분모·N/A 로직은 합성 테스트로 검증했다. manifest 시각 상태는 세 영상 모두 sampled이며 전수 검증을 뜻하지 않는다.
