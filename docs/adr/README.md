# ADR — Architecture Decision Records

ADR은 구현 완료 후 한꺼번에 작성하는 회고가 아니라 **설계 선택이 발생하는 시점에 기록**한다.

- `Proposed`: 검증 전 제안, `Accepted`: 사용자 승인 및 구현 기준, `Superseded`: 후속 결정으로 대체, `Rejected`: 미채택.
- 매 ADR은 `상태 / 배경 / 결정 / 대안과 트레이드오프 / 영향 / 재검토 조건 / 검증 근거`를 포함한다.
- 최초 6개 ADR은 사용자와 대화에서 합의된 설계 방향을 기초로 한 **Proposed** 문서다. Codex가 환경을 검토하고 사용자 승인 후 Accepted로 바꾼다.
- 실험에서 가설이 틀리면 ADR을 조용히 덮어쓰지 않고 변경 이력과 실측 결과를 남긴다.
