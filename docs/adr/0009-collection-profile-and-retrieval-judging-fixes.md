# ADR-0009 — 대상 프로필, 판정 기준·검색어 프롬프트, 중복 재검색 제거

- 상태: Accepted (사용자 승인 2026-10-21)
- 날짜: 2026-10-21
- 관련: ADR-0003(LangGraph, 재검색 상한), ADR-0008(LLM 백엔드), [roadmap-and-design-notes.md](../roadmap-and-design-notes.md)

## 배경
OpenAI 평가(v2)에서 못 찾은 질문과 확신 오답을 `WISH_AGENT_TRACE`로 열어 보니 원인이 서로 달랐다.
1. **판정이 깐깐함(화자 질문)**: 검색은 정답 청크를 3라운드 모두 찾았지만, verify가 "누가 말했는지는 자막에 없다"는 이유로 계속 `uncertain`을 줘서 `ambiguous`로 끝났다.
2. **같은 후보를 되풀이 재검색**: 재작성 검색어가 동의어 수준이라 후보 3개가 매 라운드 같았고, 그 사이 LLM을 4회 더 호출했다(필요한 것은 2회).
3. **어휘 불일치**: 질문의 핵심 명사를 번역 자막이 다른 말로 써서 정답이 후보에 한 번도 오르지 않았고, 재작성도 같은 명사를 유지했다.
4. (참고) 같은 말을 하는 장면이 여럿인 질문에서 `found`가 gold와 다른 장면을 가리킨 경우는 라벨 한계라 개선 대상이 아니다.

또한 프로젝트가 NCT WISH 전용으로 읽히지만 WISH는 첫 적용 대상일 뿐이다. 코드의 대상 종속은 공통 프롬프트 첫 줄, 이름 감지 정규식, 화면 문구 3곳이었다.

## 결정
1. **대상 프로필** (`backend/app/profile.py`, `data/profile.example.json`, 실제 파일 `data/profile.local.json`은 Git 제외)
   - 이름, 자막 언어, 번역 여부와 원래 언어, 이름 사전(표기·별칭), 메모를 담는 Pydantic 모델. 모두 기본값이 있어 없어도 동작하고, 형식이 틀리면 시작 때 실패한다. `data/` 아래 파일만 허용한다.
   - `JsonLLM`이 시스템 메시지에 프로필 안내를 붙이고(두 백엔드 공통), Router/Rewrite가 `subtitle_language`로 검색어를 쓴다. 자막 속 이름 언급(`mentioned_members`)도 프로필의 이름 사전으로 찾는다(화자가 아님).
2. **프롬프트(일반 원칙)**
   - route: 이름 사전의 표기 사용, 번역 자막이라 핵심 명사에 동의어·다른 표기를 함께 넣기, `unsupported`/`chat`은 빈 검색어 허용(ADR-0008).
   - verify: 번역이라 단어가 달라도 같은 뜻이면 인정, **화자를 알 수 없다는 것은 판정을 낮추는 이유가 아님**(내용이 있으면 `relevant`).
   - rewrite: 이전에 거절한 후보의 문구를 반복하지 않고 **핵심 명사**를 동의어·다른 표기·상하위어로 바꾸기.
3. **중복 재검색 제거(`graph.py`)**
   - State에 `judged`(후보별 이전 판정)를 두고 **아직 판정하지 않은 후보만** verify에 보낸다. 이미 판정한 후보는 이전 판정을 재사용한다.
   - 새 후보가 하나도 없으면 verify를 건너뛰고 재검색을 멈춘다(내용이 같은 재검색은 정보가 없다). 상한(최대 2회 재검색, 3라운드)·25초 예산·상태 결정표·폴백은 그대로다.
   - rewrite 입력 `feedback`을 `{verdict, quote(120자)}` 목록으로 넓힌다(기존은 ID→판정 맵).
   - 진단 trace에 `reused`(재사용한 판정 수)를 기록한다.

## 대안과 트레이드오프
- **프롬프트에 이름을 하드코딩**: 구현은 가장 쉽지만 대상이 바뀔 때 코드를 고쳐야 하고 대상 종속이 코드에 남는다. 프로필로 분리해 확장 경로를 열었다.
- **이중 검색어(영어 + 한국어 원문을 각각 검색해 합치기)**: 재현율을 더 올릴 수 있지만 그래프·MCP 호출 구조가 커진다. 이번에는 프롬프트로 같은 검색어 안에 동의어를 넣는 방식만 택하고 이중 검색은 보류했다(향후 과제).
- **같은 후보도 매 라운드 다시 판정**: 단순하지만 정보가 없는 호출이고 판정이 뒤바뀔 위험이 있다. 이미 본 후보는 재사용한다. 단점: 첫 판정이 틀리면 만회하지 못한다(대신 새 후보가 나오면 계속 검색).
- **화자 질문에서 `uncertain`을 허용**: 정직해 보이지만 화자는 항상 확인 불가로 고지되므로 내용 판정만으로 충분하다. 오답 통과가 늘 수 있어 `confident_wrong`을 확인한다.

## 결과와 한계
- **실측(OpenAI, 같은 gold, v2 → v3, 1회씩)**: C의 장면 Success@1은 16/18로 **그대로**다(화자 질문 1건 `ambiguous`→`found`, 유사 장면이 여럿인 질문 1건은 Router 검색어가 바뀌면서 다른 비슷한 장면이 `found`로 반환되어 확신 오답 +1, 프롬프트 변경이 불리하게 작용했을 가능성 포함). 화자 미확인 정확도 2/4 → 3/4, C의 LLM 호출 50 → 42, 평균 지연 2.88 → 2.57초. A/B의 `router_en`은 Router 프롬프트(동의어 포함 검색어) 효과로 A 5→13, B 13→15로 올랐다.
- **대가**: 시스템 메시지가 길어져 입력 토큰이 늘었다(C+C-ko 합계 56,941 → 70,770, 호출 수는 98 → 90). 호출 수와 토큰은 다른 방향으로 움직인다.
- 상세와 한계는 [day2-eval-openai.md](../reports/day2-eval-openai.md). gold의 실패 사례를 본 뒤의 개선이라 낙관 편향이 있을 수 있고 hold-out 확인은 못 했다. 1문항 변화는 노이즈일 수 있다.
- 프로필이 없으면 이름 사전 효과는 없다. 영어 외 자막·띄어쓰기 없는 언어는 검증하지 않았다.

## 재검토 조건
- `confident_wrong`이 늘거나 장면 정확도가 떨어지는 경우(프롬프트 변경 되돌림)
- 어휘 불일치가 여전히 주된 실패 원인인 경우(이중 검색어 도입)
- 새 대상이나 다른 언어를 붙이는 경우(언어별 분절 필요)

## 검증 근거
`test_agent.py`(같은 후보면 verify 1회·rewrite 1회 후 종료, 일부만 새 후보면 새 후보 ID만 전달, rewrite feedback에 인용문 포함), `test_profile.py`(기본 프로필에 대상 이름 없음, 이름 사전 렌더링과 단어 경계 규칙, 경로 제한, 두 백엔드에 프로필·규칙 반영, 다른 대상으로 교체). 기존 재검색 테스트는 후보가 라운드마다 바뀌는 가짜 질의로 조정했다.
