# ADR-0011 — 첫 검색에서 Router 검색어와 사용자 원문을 함께 검색 (이중 첫 검색)

상태: Proposed (구현·단위 테스트·실제 코퍼스 단발 확인 완료, **gold 정량 평가 전** — 기본값 off)

## 배경
같은 의미의 질문이 문구에 따라 `found`/`not_found`로 갈렸다. 실제 trace로 확인한 원인은 Router(LLM)가 만든 영어 검색어가 번역 자막의 어휘와 다르다는 것이다("manitto"로 검색했지만 자막은 "Secret Santa"). 같은 질문을 **한국어 원문 그대로** Hybrid 검색에 넣으면 다국어 임베딩(bge-m3)이 정답 cue를 1위로 찾았다. 즉 Router의 어휘 실수를 원문 검색이 보완할 수 있다. 기존 통제 실험에서도 C(Router 영어)와 C-ko(한국어 원문)가 같은 16/18이었다(day2-eval-openai).

## 결정
- 첫 라운드(`attempt=0`)에 `search_transcripts`를 두 번 호출한다: Router 검색어, 사용자 **원문**. 결과는 청크 ID 기준 **RRF(k=60)**로 합치고(두 검색에 모두 나온 청크가 우선, 같은 영상 10초 이내·cue 겹침은 중복 제거) 기존과 같은 최대 3개(+exclude)만 근거 확인·판정으로 보낸다. 판정 호출 수와 OpenAI로 보내는 후보 수(최대 3구간)는 그대로다.
- **재검색 라운드는 기존대로 단일 검색**이다(재작성은 검색어를 바꾸는 것이 목적). 원문으로 실제 검색했으면 `queries` 이력에 넣어 재작성이 같은 검색어를 반복하지 않게 한다.
- **건너뛰는 경우**: 원문이 Router 검색어와 같을 때, 후속 질문(`resolved_query`가 있음 — 원문이 "다른 장면도" 같은 지시어뿐), unsupported/chat(검색 없음).
- 두 번째 검색이 실패하면(`SearchFailure`) 첫 검색 결과로 계속한다(trace에 기록). 첫 검색 실패는 기존대로 오류다.
- 플래그 `WISH_DUAL_QUERY=1`(기본 off). `FinderAgent(dual_query=...)`로 주입하고 API와 평가 하네스(`eval.run_eval`, 결과 JSON의 `dual_query`)가 같은 환경변수를 읽는다. 인용·시각·URL은 여전히 원문 cue에서 결정적으로 만들며 후보 검색만 넓어진다.

## 대안/트레이드오프
- Router 모델을 `gpt-4o`로 올리기: 코드 변경이 없지만 토큰 비용이 늘고, 문구 민감성의 근본 원인(번역 어휘)은 남는다. 별도 선택지로 유지.
- Router가 대체 뜻 검색어(`alt_queries`)를 내게 하기: 이미 시험했고 gpt-4o-mini가 목록을 비워 발동하지 않아 폐기(roadmap §6).
- **비용**: 검색이 두 번이라 첫 라운드 지연이 늘고(실제 코퍼스 단발 관측: 질문당 약 +1~2초), MCP 도구 호출이 질문당 1회 늘어난다. LLM 호출·토큰은 늘지 않는다. 검색 게이트가 동시 실행 1건이라 순차 실행이다.
- 한국어 원문이 약한 질문(예: 번역 어휘가 크게 다르고 의미 임베딩도 못 맞추는 경우)에는 도움이 없고, RRF 결합이 Router 쪽 좋은 후보를 3개 한도 안에서 밀어낼 수 있다(미측정).

## 결과 / 검증
- 단위 테스트 7개 추가(기본 off, 첫 라운드만 두 검색어, 재검색은 단일, 원문 이력 반영, 동일 검색어·후속 질문·unsupported 건너뜀, 두 번째 검색 실패 시 폴백, RRF 결합·중복 제거). 백엔드 전체 160 통과·1 skip.
- 실제 코퍼스 단발 확인(OpenAI, 질문당 1회, **gold 평가 아님**): 기능 off에서 `not_found`(3라운드, 약 8초)였던 마니또 질문 두 문구가 on에서는 둘 다 1라운드에 정답 시점(3:09)을 `found`로 반환했다. 장면 질문 6개는 on에서도 같은 시점을 찾았고 범위 밖 질문은 그대로 거부했다.
- **미측정**: gold 20문항 A/B/C 재측정(정확도·지연·호출·토큰), 확신 오답 증감, 반복 분산. 이 결과 전까지 기본값을 켜지 않는다.

## 재검토 조건
gold 재측정에서 Scene Success@1이 오르지 않거나 확신 오답이 늘면 철회하거나 off로 유지한다. 개선이 확인되면 기본값을 on으로 바꾸고 이 ADR을 Accepted로 갱신한다.
