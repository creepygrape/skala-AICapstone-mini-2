# ADR-0006 — 결과 카드에서 YouTube iframe 임베드로 장면을 바로 확인한다

## 배경
결과 카드가 YouTube 새 탭 링크만 제공해 시연 흐름이 끊겼다. 서버는 이미 `video_id`, `start_seconds`, `end_seconds`를 반환한다.

## 결정
각 결과 카드에 플레이어를 바로 표시한다(버튼 없음, 자동 재생 없음). 직접 iframe 대신 IFrame Player API(`https://www.youtube.com/iframe_api`, 키 불필요)로 생성해 `onError` 코드(2/5/100/101/150/153)를 화면에 사유와 함께 표시한다. 시연 중 재생 실패 원인을 알 수 없어 직접 iframe 방식을 대체했다. API 키·Data API는 사용하지 않는다. `video_id`는 프론트에서도 `^[A-Za-z0-9_-]{11}$`로 검증한다. 기존 링크는 'YouTube에서 열기'로 유지해 임베드 차단 영상(오류 101/150)의 폴백으로 둔다. 인용문·시각 표시는 원문 cue 기준 그대로이며 영상 내용을 분석했다고 주장하지 않는다.

## 시연 중 확인된 사항 (2026-10-21)
- 같은 영상이 `http://localhost:5173`에서는 카드 안에서 재생되고 `http://127.0.0.1:5173`에서는 일부 영상(`1HJgbE66GI4`, `vWjPXwKV_Y8`)이 오류 코드 150으로 막혔다. 원인은 접속 origin 차이로 추정하며 YouTube 측 동작은 직접 검증하지 못했다. 따라서 시연·개발은 `localhost`로 접속한다.
- 재생이 막히면(101/150) 플레이어 영역을 접고 안내 한 줄과 'YouTube에서 열기' 링크만 남긴다(썸네일 대체 방식과 비교 후 접기 방식 채택). 그 외 오류는 코드와 사유를 표시한다.

- 같은 영상(`video_id`)의 결과는 화면에서 카드 한 장으로 묶는다. 카드에는 플레이어 하나와 장면 항목(타임스탬프 버튼·원문 인용문·설명)을 순위순으로 나열하고, 플레이어 시작 시각과 'YouTube에서 열기' 링크는 최상위 순위 항목 기준이다. 묶기는 프론트 표시 전용이며 백엔드 결과·평가 단위(결과별)는 바뀌지 않는다.

## 대안과 트레이드오프
- 직접 iframe: 단순하지만 실패 시 오류 코드를 알 수 없음(시연에서 문제 확인). Player API는 외부 스크립트 1개가 추가되지만 오류 진단이 가능해 채택.
- 새 탭 유지: 구현 0이지만 시연 흐름이 끊김.
- youtube-nocookie.com: 처음 채택했으나 시연 중 localhost에서 '이 동영상은 볼 수 없습니다'가 발생(영상은 공개·임베드 허용, 새 탭 재생 정상)해 표준 도메인 + `origin`으로 변경.
- `end` 파라미터: 처음엔 근거 구간 종료 시 정지하도록 넣었으나 시연에서 맥락을 볼 수 없어 제거했다. 대신 카드의 시간 버튼(`▶ 3:09 – 3:11`)이 `seekTo(start)`+`playVideo()`로 근거 시작 지점부터 다시 재생한다. 임베드를 쓸 수 없으면 버튼은 YouTube 새 탭으로 폴백한다.

## 영향 및 검증
신규 의존성·비용 없음. 외부 iframe이므로 CSP 도입 시 `frame-src https://www.youtube.com` 필요. 검증: App.test.js(카드 내 플레이어 렌더), scripts/browser_smoke.py(iframe src에 start=189, 실행 전). 카드 수만큼 플레이어가 생성되므로 결과 수가 많아지면 지연 로딩 재검토.

## 재검토 조건
임베드 차단 영상 비율이 높거나 정확한 구간 종료·카드 간 전환이 필요할 때 Player API 도입.
