# ADR-0010 — 대화형 3단 UI, 브라우저 검색 기록, 후속 질문 맥락

상태: Accepted (사용자 승인 계획 기준, 구현·단위 테스트 완료)

## 배경
단일 스크롤 폼은 이전 검색·결과가 사라지고, 결과 카드에는 인용 cue 1개만 보여 "그 앞뒤에 무슨 말이 있었나"를 확인할 수 없었다. 팬이 기억을 더듬어 여러 번 묻는 흐름에 맞춰 대화형 UI, 기록, 앞뒤 자막, 후속 질문이 필요했다. 로그인은 없다.

## 결정
- **레이아웃**: 좌 기록 사이드바 / 중 대화(사용자 말풍선 + 에이전트 말풍선) / 우 선택 장면 패널(영상 + 주요 자막). 1180px 이하는 사이드바·패널을 슬라이드 패널로 전환한다. Vue 3 SFC, 신규 의존성 없음.
- **에이전트 말풍선 = 진행 상황만**: 기존 SSE 이벤트(`routing/searching/validating/replanning`)를 단계로 표시하고 완료 후 "검색 진행 과정 보기"로 접는다. 검증 후 `result`만 카드로 표시하는 ADR-0005 원칙 유지. 대사 같은 자유 서술은 만들지 않는다.
- **기록 저장소 = 브라우저 localStorage**(`wish-finder:conversations:v1`, 최대 30대화, 용량 초과 시 오래된 대화부터 삭제, 읽기·쓰기 실패 무시). 서버 저장은 사용자 구분이 없어 모든 방문자가 같은 기록을 보게 되고, 인용 자막이 서버에 남기 때문에 채택하지 않았다. 기기 간 공유는 불가하다. 사이드바 항목은 저장된 결과를 복원하며 재검색하지 않는다. 실행 중 닫힌 턴은 "중단됨"으로 표시한다.
- **앞뒤 자막**: 새 MCP 도구 `get_cue_neighbors(video_id, cue_id, before≤5, after≤5)`와 `GET /api/videos/{video_id}/cues/{cue_id}/context`. 원본 cue를 같은 영상 안에서만 순서대로 반환하고(경계 clamp, 영상 간 혼합 금지) 알 수 없는 ID는 오류다. UI는 MCP에 직접 접근하지 않는다. 기본 앞뒤 3개로 발췌만 보여 준다(requirements §저작권). 기존 `get_scene_context`(앞쪽 창)는 변경하지 않는다. 읽기 전용이라 `busy`와 무관하다.
- **후속 질문(P1 확장)**: 서버는 무상태를 유지한다. 클라이언트가 같은 대화의 최근 3턴(`history`: 질문 + 상위 결과 요약)과 이미 보여 준 장면 키(`exclude`, `video_id:cue_id`, 최대 20)를 요청에 싣는다. Router 프롬프트에 `previous_turns`가 있을 때만 "대명사/생략 해석에만 사용, 근거 아님" 지침을 붙여 독립 검색어(`resolved_query`)를 만든다. **원래 질문과 이전 턴은 불변**이며 `resolved_query`는 검색과 재검색(rewrite 입력)에만 쓰는 별도 필드다(PR #11 리뷰 P1: Router 출력이 검증 기준까지 덮어쓰면 잘못된 재작성이 스스로 `found`를 확정하는 자기 확증이 생긴다). 의미 검증에는 원 질문 + 제한된 history(최대 3턴) + `resolved_query`를 함께 보내되, "판정 기준은 원 질문과 이전 턴이고 resolved_query에만 있는 세부사항으로 relevant를 판정하지 않는다"는 지침을 붙인다. 이 마지막 규칙은 LLM 프롬프트 계약이며 결정적 검사가 아니다. `exclude`는 서버에서 중복을 제거하고, search 도구 시그니처를 바꾸지 않고 `top_k=3+len(exclude)`(≤20)로 더 가져온 뒤 **검색 응답의 `selected_cue_id`로 제외 후보를 먼저 거르고 남은 최대 3개만** `get_scene_context`로 근거 확인한다(문맥 조회 수는 결과 상한에 비례, exclude 길이와 무관). 근거 확인 후 키가 다르게 풀린 경우를 위해 사후 필터도 유지한다. 제외로 비는 것은 `evidence_rejected`로 취급하지 않는다. 두 필드가 없으면 기존 경로와 동일하다(회귀 테스트). 재검색 상한·SSE 이벤트 종류·순서는 불변.
- **범위 제외**: 일치율(%) 점수, 정렬 탭, 북마크, 장면 요약, 관련 장면 추천. 검증 점수가 아닌 수치가 일치도로 오인되고, 요약은 원문 근거를 벗어난 서술이 될 수 있다.

## 대안/트레이드오프
- 서버 SQLite 기록/체크포인터+thread_id: 기기 간 공유는 가능하나 사용자 구분 없음, lifespan·의존성·ADR 부담. 기각.
- result 이벤트에 맥락 cue 포함: 추가 요청은 없으나 SSE 스키마·기존 테스트 변경이 큼. 기각.
- exclude를 MCP search 인자로 전달: 정확하지만 도구 계약 변경이 큼. 우선 후처리로 구현하고 재검토.
- 후속 질문 재작성은 LLM 품질에 의존한다. 무LLM 키워드 모드(`WISH_AGENT_ENABLED` 미설정)는 `history/exclude`를 쓰지 않는다.

## 결과 / 검증
- 백엔드 pytest(신규: 앞뒤 cue 경계·404·422·busy 중 조회, 원 질문 불변·resolved_query 분리 전달, 재검색이 resolved_query에서 시작, exclude 사전 필터·문맥 조회 수 상한). 실제 통과 수는 PR 본문의 최신 실행 결과를 따른다.
- 프론트 vitest 35 통과(신규: 저장/복원/손상 저장소/용량 초과, 후속 payload, 카드·패널·사이드바 렌더). `npm run build` 성공.
- 합성 fixture + 키워드 모드에서 Chrome(CDP)로 확인: 결과 카드 → 앞뒤 자막 강조 → 두 번째 질문 → 새로고침 후 기록 복원. **미측정**: 실제 LLM 후속 질문 품질, 실제 영상 재생/seek, 평가(A/B/C) 지표(검색 경로 불변이라 재측정하지 않음).

## 재검토 조건
기기 간 기록 공유가 필요하거나, 후속 질문 오작동이 평가에서 확인되거나, localStorage 용량이 부족할 때.
