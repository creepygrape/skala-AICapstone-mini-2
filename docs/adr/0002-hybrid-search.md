# ADR-0002 — 장면 기억 검색은 BM25 + 다국어 Dense의 Hybrid로 구축한다

- 상태: Proposed
- 날짜: 2026-10-20
- 관련 요구사항: FR-03, FR-04, FR-05, FR-07, FR-16

## 배경
사용자는 정확한 대사가 아닌 상황만 기억한다. 원본 추출 스크립트가 영어일 수 있지만 사용자 질문은 한국어일 수 있다. 이 언어 차이는 **사용자 불편함 자체가 아니라** 검색 파이프라인이 처리할 기술적 제약이다.

## 결정
BM25 기반 정확 용어 검색과 다국어 의미 임베딩 검색을 함께 사용한다. 단순한 RRF로 순위를 융합하는 방안을 우선 검토한다. 검색 인덱스는 영상별 cue 식별자와 타임스탬프를 보존한다. 한국어 쿼리→영어 검색어 재구성은 기본 인덱스/임베딩 성능을 측정한 후 필요 시 사용한다.

## 대안과 트레이드오프
- BM25 단독: 가볍고 빠르나 상황의 의역·다국어 표현에 취약할 수 있음.
- Dense 단독: 의역에 강할 수 있으나 고유명사·세부 인용의 정확한 매칭이 약할 수 있음.
- Hybrid: 추가 의존성·인덱스 비용 및 튜닝 필요, 대신 보완적 신호 사용 가능.

## 영향 및 검증
Baseline A=BM25, B=Hybrid, C=Hybrid+Agent를 같은 corpus/평가셋에서 비교한다. 소규모 SRT 3편에서 Hybrid 성능이 항상 더 높다고 가정하지 않는다.

## 재검토 조건
한국어 질문에 대한 다국어 임베딩 성능/latency가 실측에서 나쁘거나 핵심 질문에서 BM25 단독이 더 나은 경우.

## Day 1 구현 기준 (2026-10-20)
기존 bge-m3 캐시만 사용하고 새 모델 다운로드를 금지한다. NumPy 벡터 검색과 BM25, RRF k=60을 사용한다. 모델은 한 프로세스에만 로드한다. 모델 로딩·검색 품질은 아직 미측정이다.

## Day 1 검색 상세 결정
BM25는 rank-bm25의 BM25Plus를 사용한다. 소규모 합성 corpus에서는 Okapi의 IDF가 0이 되어 실제 일치도 누락되는 사례가 있어 이를 회귀 테스트로 확인했다. BM25Plus의 비일치 기본 점수 때문에 실제 토큰 교집합이 있는 후보만 keyword 순위에 포함한다. Dense는 정규화 벡터의 내적, 융합은 RRF k=60, 각 검색의 후보 상한은 20이다.
검색 인덱스는 NumPy 파일로 로컬 data/index에 저장하며 corpus·청킹 텍스트·모델 로컬 경로의 해시로 무효화한다. Chroma를 추가하는 대신 설치 복잡도를 줄이며 대규모 검색 확장은 추후 검토한다.

## PR #1 리뷰 반영 — 질의 임베딩 재사용

검색 라운드당 질의 벡터를 한 번 계산하고 후보 cue 선택에 재사용한다. 영상별 cue ID 맵은 Retriever 초기화 시 한 번 만든다. keyword 모드의 cue 선택은 어휘 일치만 사용하며, 임베딩 모델이 로드돼 있어도 질의 임베딩을 호출하지 않는다. 계수형 합성 encoder 테스트로 hybrid 질의 encode 1회와 keyword encode 0회를 확인한다.

## Day 1 마무리 평가 기준

개발 질문 5개를 실제 cue에서 별도 라벨링하고 A=BM25Plus, B=Hybrid를 동일 corpus·질문·정답으로 비교한다. 한국어 원문 조건과 질문 텍스트만으로 로컬 qwen3:8b가 한 번 생성해 고정한 영어 재구성 조건을 분리한다. 재구성 출력이 잘못돼도 정답을 보고 수정하지 않으며 언어 변환 실패를 별도 기록한다. gold 초안은 결과 튜닝에 사용하지 않는다.

평가는 검색 도구의 검증된 cue 시작 링크 한 점을 정답 영상·허용 구간(±10초)과 비교한다. 라운드 latency는 검색·MCP 원문 조회·결정적 검증을 포함하고, 초기 모델/인덱스 준비 및 재구성 생성 시간은 분리한다. 소표본 결과는 건수와 문항별 결과를 우선 보고하며 Agent C·기권 정확도·의미 검증 성능을 측정한 것처럼 표현하지 않는다.

원본·gold·개별 실행 결과는 비공개 eval/private/에 보관하고 공개에는 스키마·합성 예시·요약만 둔다. 실제 영상 시간 일치는 사용자 수동 확인 전까지 미확인이다.

## PR #2 평가 일관성 결정

API와 A/B는 질의 검증·MCP 호출·후보별 원문 검증·상태/경고를 공용 서비스로 수행한다. 단순 복사 대신 공유하여 파이프라인 차이를 방지한다. 원문 검증 실패는 후보 제외로, 도구 실패는 오류로 분리한다. 평가에는 status/warnings/오류/도구 호출 수를 기록하고 중단 시 완료 결과와 미실행 목록을 비공개에 저장한다.

근거 없음·화자 미확인 지표를 별도 분모로 기록하고 문항 없음은 N/A다. A/B는 범위 밖 의도 라우터가 없어 범위 밖 정확도는 미지원 N/A로 표시한다. 후보 원문 검증 실패의 unsupported는 범위 밖 판정 성공으로 세지 않는다. Scene Success/Hit@3와 화자 unknown 고지는 별개로 집계한다.

모든 CLI 경로는 ROOT 기준으로 해석하고 출력은 해석된 eval/private 내부로만 제한한다. 경로 이탈·심볼릭 링크 탈출을 거부한다. 모든 근거 cue가 정답 구간에 포함되고 모든 정답 구간에도 근거 cue가 있어야 한다. 중복 video_timing_verified 라벨은 제거하며 manifest 시각 상태를 실행 결과에 기록한다. 실행 중 모델/도구 오류를 not_found로 숨기지 않고 오류 문항을 포함한 분모와 미완료 여부를 보고한다.

검증은 API/평가 동일 결과, 공백 질의, 후보 실패, 시각 경고, 출력 경로 탈출, 근거 없는 정답 구간, 중단 결과 보존을 회귀 시험한다. 기존 개발 질문/고정 재구성만 재실행하며 gold 초안은 사용하지 않는다.
