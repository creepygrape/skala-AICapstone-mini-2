# ADR-0003 — 역할 분리 LangGraph와 조건부 최대 2회 재검색

- 상태: Accepted (사용자 확정, 구현·통합 검증 전)
- 날짜: 2026-10-20
- 관련 요구사항: FR-06, FR-07, FR-09, FR-14, FR-15

## 배경 및 변경 이력
단일 검색 결과가 질문의 상황과 다르거나 근거가 모호하면 검색어 변경과 문맥 검증이 필요하다. 무제한 재계획은 지연과 호출 비용을 증가시킨다.

초기 Proposed 문서는 재검색 상한을 1회로 제안했다. 2026-10-20 사용자 확정에 따라 **조건부 최대 2회 재검색, 최초 검색 포함 최대 3라운드**로 변경한다. 이 승인은 상한 변경에 대한 것이며 검색 품질 향상이나 구현 완료를 의미하지 않는다.

## 결정 및 선택 이유
Router/Supervisor → Search → Context Expansion → Verification → Finalize 역할 분리를 유지한다. Search는 후보 탐색, Verification은 원문 무결성과 의미 적합성 확인을 담당한다. 추가 검색 기회를 확보하면서도 결정적인 종료 상한을 둔다.

- `MAX_REPLAN_ROUNDS=2`. `attempt`는 실행할 검색의 0 기반 인덱스로 최초 0, 첫 재검색 1, 두 번째 재검색 2다.
- 근거가 충분하면 해당 라운드에서 즉시 Finalize한다. 부족하고 `attempt < 2`이며 요청 시간 예산이 남아 있을 때만 Replan에서 검색어/전략을 바꾸고 `attempt`를 정확히 1 증가시킨다.
- `attempt=2`에서 다시 검색하지 않는다. 최종 결과는 기존 `found/ambiguous/not_found/unsupported/partial/error` 계약에 따라 결정한다.
- 검색 결과 없음은 근거 부족으로 재계획할 수 있다. MCP 장애·LLM timeout을 빈 검색으로 바꿔 재검색하지 않고 오류/부분 결과 경로로 처리한다.
- 호출별·전체 요청 timeout은 별도로 유지한다. 시간 예산이 소진되면 남은 검색 기회를 채우지 않고 종료한다.
- 원문·시간·영상 ID는 결정적 코드로 검증한다. 검증 전 답변이나 후보는 스트리밍하지 않는다. 화자 추정 금지 정책도 유지한다.
- SSE `attempt`는 0/1/2, `replanning` 이벤트는 최대 2회다. `search_attempts`는 실제 실행한 검색 라운드 수로 검색하지 않으면 0, 최대 3이다.
- 역할 분리 Graph를 독립 Multi-Agent로 과장하지 않는다.

## 대안 비교 및 트레이드오프
- 재검색 없음: 빠르고 단순하지만 최초 검색 실패를 복구하지 못한다.
- 기존 상한 1회: 지연·호출 상한이 낮지만 두 번째 검색에서도 부족하면 복구 기회가 제한된다. 이번 사용자 결정으로 대체한다.
- **상한 2회(채택)**: 추가 검색 기회를 주되 총 3라운드로 제한한다. 최악 경로의 Tool/LLM 호출·latency·유료 모델 사용 시 비용은 증가할 수 있다.
- 무제한 재검색: 품질 향상을 보장하지 못하면서 시연 시간과 비용 상한을 잃으므로 제외한다.

## 영향
State 주석, 조건부 edge, SSE 진행 상태, 평가의 검색 횟수 기록과 테스트 기대값을 함께 맞춘다. 원문 데이터 구조, 검색 알고리즘, API 이벤트 이름, 웹 UI 구성과 P0 범위는 변경하지 않는다. 기존 15초 응답 목표의 달성 여부는 재측정하며 미리 보장하지 않는다.

## 검증 방법 및 현재 근거
설치된 `langgraph 1.2.16`에서 `StateGraph`, 비동기 노드 등록용 `add_node`, `add_conditional_edges`의 import와 시그니처를 확인했다. 제품 Graph는 아직 구현하지 않았으므로 아래는 **예정 검증**이다.

1. 첫 검색 성공: `attempt=[0]`, 검색 1라운드, 재계획 0회.
2. 첫 재검색 성공: `attempt=[0,1]`, 검색 2라운드, 재계획 1회.
3. 두 번째 재검색 성공 또는 계속 불충분: `attempt=[0,1,2]`, 검색 3라운드, 재계획 2회, 네 번째 검색 금지.
4. 충분한 근거가 생긴 뒤 추가 검색 금지, timeout/도구 장애의 오류 분기, 요청 시간 예산 소진 시 조기 종료.
5. 검증 실패 초안 미노출, SSE 카운터·최종 search_attempts와 실제 Tool 호출 trace 일치.
6. 고정 corpus·질문·정답으로 A/B/C를 비교하고 0/1/2회 재검색별 성공 건수·latency·호출 수를 보고한다. 현재 측정값은 없다.

## 재검토 조건
두 번째 재검색의 개선 효과가 없거나 지연·메모리·호출 비용이 시연 목표를 해치는 경우 근거를 제시해 재검토한다. 상한·P0 변경은 사용자 승인 후 반영한다.
